# 자동로그인 기획 · 정식 v1.0.0 포함

진행 순서: 기획 → 개발 → QA → Wiki.

## 배포 전 지연·RSA 리다이렉트 회귀 수정

- 확인한 로그에서 사이트 탐색은 약 0.02~1.62초, 로그아웃 후 재로그인 전 앱의 중복 프로필 정리는 합계 약 7.3초였다. RSA 중간 페이지를 인증 실패로 오인하면서 저장 입력을 지우고 경고창을 띄웠으며, 경고 확인 대기가 9~26초 추가됐다. 사용자 입력·경고 확인 시간을 서버 지연으로 합산하지 않는다.
- 수동 로그인 창을 먼저 표시하고 페이지를 준비한다. 로그아웃은 쿠키·사이트 저장소만 한 번 삭제하며 다운로드 캐시를 유지한다. 취소한 정리가 끝나기 전에 새 정리·자동 인증이 겹치지 않게 한다.
- RSA 중간 페이지에서는 입력을 유지한다. 인증된 최종 페이지의 계정 ID와 조직 메뉴를 확인한 뒤 저장하고 조직도를 읽는다. 실제 실패 폼·탐색 오류·취소에서는 입력을 폐기한다. 성공 후 같은 홈 페이지를 다시 요청하지 않는다.
- 캘린더의 `UserSession`은 로컬 신원 복원으로 시작 시 사이트 재인증을 생략한다. 주간보고 앱은 로그인된 최신 웹페이지에서 조직도를 읽어야 하므로 웹 세션 확인을 유지한다. 캘린더의 최종 인증 요소 확인, 제출 여부 확인, 저장 후 되읽기 검증을 참고한다. 캘린더 DB·세션 파일·프로필에 의존하지 않는다.
- 로그인 함수가 제출하지 않으면 즉시 수동 전환하고, 제출 후 응답이 멈춘 경우에는 기존 합계 20초 제한을 유지한다. 브라우저 환경 생성·초기화, 세션 정리, 로그인창 표시와 페이지 준비를 별도로 기록한다.
- QA는 실제와 같은 `form.submit()` 및 RSA HTML → 지연된 JavaScript 홈 리다이렉트로 재현한다. 중간 페이지 입력 유지, 자동 인증 성공, 실제 실패 입력 폐기, 중복 정리 방지, 로딩 중 취소·재로그인을 검증한다.

## 사용자 흐름

- 로그인 창 하단에 ‘자동로그인’ 체크박스와 ‘공용 PC에서는 체크하지 마세요. 다음 실행부터 이 계정으로 자동 로그인됩니다.’를 표시한다. 기본 해제.
- 체크하고 수동 인증에 성공한 경우에만 입력한 계정 정보를 저장한다. 원본 사이트의 RSA 로그인 함수를 그대로 호출한다.
- 저장 정보가 있으면 시작 시 기존 세션을 확인한다. 계정 확인까지 성공한 세션만 재사용하고, 만료됐으면 자동 인증을 실행당 최대 1회 수행한다.
- 자동 인증 실패·20초 제한·서버/연결 오류·인증 페이지 구조 변경은 자동 반복하지 않고 안내와 수동 로그인창으로 전환한다. 인증 거부와 통신 실패를 구분한다.
- 비밀번호 변경, 잠금, 사용 중지 등은 사이트가 제공한 인증 거부로 처리한다. 서버 응답이 구분하지 않는 상태를 앱이 임의로 단정하지 않는다.
- 로그인창을 닫으면 인증되지 않은 앱이 남지 않도록 시작 시 종료한다. 실행 중 인증 취소 시 기존 계정 화면을 정리하고 재로그인 버튼을 제공한다.
- 상단에 현재 계정과 ‘로그아웃’ 표시. 로그아웃은 자동로그인 정보, 앱 WebView2 쿠키/사이트 저장소, 조직도/참석자/보고서를 정리하고 수동 로그인으로 돌아간다. 서버 로그아웃은 확인된 엔드포인트가 없으면 호출하지 않는다.
- 다른 계정으로 로그인하면 이전 조직/선택/보고서를 재사용하지 않는다. 보기 배율 등 공통 환경 설정은 유지한다.

## 저장/로그 정책

- 실행 폴더의 평문 config 대신 사용자 AppData의 별도 인증 파일을 사용한다. DPAPI CurrentUser로 계정/비밀번호 전체를 암호화한다. 외부 패키지는 추가하지 않는다.
- 자동로그인 해제 및 로그아웃 시 인증 파일 삭제. 삭제 불가 시 성공한 것처럼 표시하지 않고 오류를 안내한다.
- 로그인 실패 입력은 기존 저장 정보에 덮어쓰지 않는다. 손상/복호화 불가 정보는 자동 인증에 사용하지 않고 수동 로그인으로 전환한다.
- 비밀번호/암호문/쿠키/인증 토큰/로그인 POST 본문은 진단 로그에 남기지 않는다. 자동 로그인 시작/성공/실패 분류/제한/로그아웃만 기록한다.
- 같은 Windows 계정을 공유하는 사람은 해당 계정의 보호 데이터에 접근할 수 있으므로 공용 계정에서는 사용하지 않는다.

## QA 완료 기준

실제 WebView2에서 정상/만료/잘못된 비밀번호/잠금/사용 중지/네트워크/서버 오류/20초 제한/손상 파일/다른 사용자 키/저장 실패/해제/로그아웃/계정 전환/비밀 로그 누출을 검증한다. 실제 사내 계정을 잠그지 않고 모의 응답을 사용한다. 다른 Windows 사용자 실행은 별도 사용자 환경이 없으면 미실행으로 기록하고 잘못된 DPAPI 키의 거부를 자동 검증한다.

QA 결과를 먼저 기록한 후 사용자 안내, 오류 대응, 테스트 결과를 GitHub Wiki와 저장소 문서로 공개한다. 새 설치본의 설치/제거와 아이콘 검사도 통과해야 배포한다.
